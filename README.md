# 🛡️ Guardian

Discord-бот для модерации и вовлечения с полноценным веб-дашбордом.
Написан на Python: **discord.py 2.x + FastAPI + SQLite**.

## Возможности

### Модерация
- предупреждения с историей, причинами и снятием по ID;
- автоматические наказания за N предупреждений (тайм-аут, мут, кик, бан);
- временные тайм-ауты (до 28 дней — лимит Discord);
- муты ролью или встроенным тайм-аутом;
- баны, в том числе временные, с автоматическим разбаном;
- кики, очистка сообщений;
- единая история дел (`/cases`, `/case view`), изменение причины и досрочное завершение.

### Логи
- вход и выход участников, смена ника и ролей;
- аватар участника в каждом логе, где он известен;
- удаление, редактирование и массовое удаление сообщений;
- вход, выход и перемещение по голосовым каналам;
- создание, удаление и изменение каналов и ролей;
- баны, разбаны и отдельный канал для действий модераторов;
- приглашения, ветки, изменение сервера и эмодзи;
- игнорирование отдельных каналов и пользователей;
- все события включаются и выключаются в дашборде.

### Роли
- автороли при входе;
- восстановление ролей после повторного входа (sticky roles, включается отдельно);
- панели ролей с постоянными кнопками: множественный выбор или «только одна роль»;
- управление панелями из дашборда и командой `/panel`.

### Прогресс
- опыт за сообщения и время в голосовых каналах;
- уровни, уведомления и роли за уровни;
- баллы лояльности;
- магазин ролей за баллы;
- достижения с наградами (роль и/или баллы) и прогрессом;
- карточка `/rank`, топы `/leaderboard` и `/loyalty top`.

### Дашборд
- вход через Discord OAuth2, доступ только с правом «Управлять сервером»;
- обзор сервера, последние наказания и топы;
- настройка логов, авторолей, панелей, модерации, XP, достижений и магазина;
- поиск и множественный выбор каналов/ролей с наглядными чипами;
- публикация и обновление панелей ролей прямо из браузера.

## Стек

| Слой | Технология |
|---|---|
| Бот | `discord.py` 2.x, `commands.Cog` + `app_commands` |
| Веб | `FastAPI`, `Jinja2`, `uvicorn` |
| БД | SQLite (WAL), доступ через `sqlite3` + `asyncio.to_thread` |
| HTTP-клиент | `httpx` |

## Быстрый старт

### 1. Требования

- Python **3.11+**;
- приглашённый бот с нужными правами;
- OAuth2-приложение Discord (для дашборда).

### 2. Установка

```bash
git clone <repo-url> guardian
cd guardian
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/macOS
source .venv/bin/activate

pip install -r requirements.txt
copy .env.example .env   # Windows
# cp .env.example .env   # Linux/macOS
```

Заполните `.env`.

### 3. Приложение в Discord Developer Portal

1. Создайте приложение: <https://discord.com/developers/applications>.
2. **Bot → Reset Token** — скопируйте токен в `DISCORD_TOKEN`.
3. На вкладке **Bot** включите:
   - **Server Members Intent**;
   - **Message Content Intent**.
   Без них бот не увидит участников и содержимое сообщений.
4. **OAuth2**:
   - скопируйте `Client ID` в `DISCORD_CLIENT_ID`;
   - **Reset Secret** → `DISCORD_CLIENT_SECRET`;
   - в **Redirects** добавьте `DASHBOARD_URL/auth/callback`, например
     `http://localhost:8000/auth/callback`.
5. Пригласите бота на сервер. Ссылку можно взять в дашборде на странице
   списка серверов (кнопка «Добавить») или собрать вручную:
   `https://discord.com/oauth2/authorize?client_id=CLIENT_ID&permissions=1099780189318&scope=bot%20applications.commands`.

Права бота: просмотр каналов, отправка сообщений, эмбеды, вложения, история,
управление сообщениями и ролями, кик, бан, тайм-ауты, просмотр журнала аудита.

### 4. Запуск

```bash
python run.py
```

- бот подключается к Discord;
- дашборд поднимается на `http://localhost:8000`;
- база создаётся автоматически в `data/bot.db`.

Полезные режимы:

```bash
python run.py --dashboard-only     # только дашборд (бот выключен)
python run.py --bot-only           # только бот, без веб-сервера
python run.py --port 8080          # другой порт
python run.py --log-level DEBUG
```

Если меняете порт через `--port`, обновите `DASHBOARD_URL` и redirect URI
в Developer Portal — иначе OAuth-вход не сработает.

При первом запуске глобальные слэш-команды могут появляться до часа.
Для разработки укажите `DEV_GUILD_ID` — команды синхронизируются с тестовым
сервером мгновенно.

### 5. Вход в дашборд

Откройте `DASHBOARD_URL`, нажмите «Войти через Discord» и выберите сервер,
где у вас есть право «Управлять сервером». Бот уже должен быть на этом сервере.

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `DISCORD_TOKEN` | да | Токен бота |
| `DISCORD_CLIENT_ID` | для дашборда | Application ID |
| `DISCORD_CLIENT_SECRET` | для дашборда | OAuth2-секрет |
| `DASHBOARD_URL` | да | Публичный адрес дашборда, он же база redirect URI |
| `DASHBOARD_HOST` | нет | Адрес прослушивания, по умолчанию `0.0.0.0` |
| `DASHBOARD_PORT` | нет | Порт, по умолчанию `8000` |
| `DATABASE_PATH` | нет | Путь к SQLite, по умолчанию `data/bot.db` |
| `SESSION_TTL_DAYS` | нет | Срок жизни веб-сессии, по умолчанию `7` |
| `DEV_GUILD_ID` | нет | ID сервера для мгновенной синхронизации команд |
| `LOG_LEVEL` | нет | `INFO`, `DEBUG`, `WARNING` |

В продакшене `DASHBOARD_URL` должен быть `https://…`: тогда cookie сессии
автоматически получают флаг `Secure`.

## Как это работает

### Предупреждения и автонаказания

При выдаче предупреждения бот считает активные варны. Если количество совпало
с правилом из настроек (например, `3 → тайм-аут 1h`), наказание применяется
автоматически, создаётся дело и отправляется лог. Снятые предупреждения
не учитываются.

### Временные наказания

Каждые 30 секунд фоновый ког проверяет истёкшие дела:

- тайм-аут — снимается `member.timeout(None)`;
- мут ролью — роль удаляется;
- бан — выполняется `guild.unban`.

Если бот был выключен, просроченные наказания снимутся после запуска.
При отсутствии прав дело закрывается с пометкой об ошибке, чтобы не зациклиться.

### Опыт и уровни

Суммарный опыт для уровня `n`: `100 × n × (n + 1) / 2`.

| Уровень | Всего XP |
|---|---|
| 1 | 100 |
| 2 | 300 |
| 3 | 600 |
| 5 | 1 500 |
| 10 | 5 500 |
| 25 | 32 500 |

За сообщение начисляется случайное число от `xp_min` до `xp_max` не чаще
раза в `xp_cooldown` секунд. За голос — `xp_voice_per_min` раз в минуту,
если в канале есть хотя бы два человека и участник не в AFK и не выключил звук.
Исключённые каналы и роли не дают опыта.

При достижении уровня бот выдаёт роли, отправляет уведомление и проверяет
достижения. В тексте уведомления доступны `{user}`, `{level}`, `{xp}`.
Лояльность можно включить отдельно от опыта: тогда сообщения и голос
продолжают приносить баллы, но уровни не растут.

### Лояльность и магазин

Баллы начисляются за сообщения и голос параллельно с опытом. В магазине
участник тратит баллы и получает роль. Если выдать роль не удалось, покупка
автоматически отменяется и баллы возвращаются.

### Достижения

Стартовый набор создаётся при первом запуске на сервере: первые сообщения,
100/1000 сообщений, час и 10 часов в голосе, 5/25 уровней, 500 баллов,
30 дней на сервере. Можно добавлять свои достижения с условием:

- сообщения;
- минуты в голосе;
- уровень;
- баллы лояльности;
- дни на сервере.

Награда — роль и/или баллы. Проверка идёт при получении опыта и раз в 6 часов
для «дней на сервере».

### Панели ролей

Кнопки используют постоянные `custom_id`, поэтому работают после перезапуска
бота. Нажатие проверяет права бота и иерархию ролей. В режиме «один выбор»
бот снимает другие роли этой панели. Если роль удалена, кнопка перестаёт
работать, а дашборд помечает её как отсутствующую.

## Docker

```bash
cp .env.example .env
# заполните .env, для контейнера удобно:
# DASHBOARD_URL=https://bot.example.com
docker compose up -d --build
```

База хранится в `./data`, порт — `8000`. Не забудьте про reverse proxy
(nginx/Caddy) и HTTPS для OAuth.

## Установка на Ubuntu

Для VPS на Ubuntu 22.04/24.04 есть готовый установщик: systemd-сервис,
nginx, отдельный системный пользователь, конфигурация в `/etc` и база
в `/var/lib`.

```bash
sudo bash deploy/install.sh --domain bot.example.com
sudo nano /etc/guardian/guardian.env
sudo systemctl restart guardian
```

Для сервера `51.250.79.201` без домена используйте SSH-туннель:
установите без `--domain`, оставьте `DASHBOARD_URL=http://localhost:8000`
и откройте туннель:

```bash
ssh -L 8000:127.0.0.1:8000 <user>@51.250.79.201
```

Публичный HTTPS-дашборд требует домена с A-записью на этот IP.

Полная инструкция по TLS, firewall, обновлению и бэкапам:
[docs/UBUNTU.md](docs/UBUNTU.md).

Коротко:

```bash
sudo bash /opt/guardian/deploy/update.sh --source /tmp/guardian-new
sudo /opt/guardian/deploy/backup.sh
sudo journalctl -u guardian -f
```

## Эксплуатация

- **Бэкап.** Остановите бота и скопируйте `data/bot.db` (и `-wal`, `-shm`),
  либо используйте `sqlite3 data/bot.db ".backup backup.db"`.
- **Логи.** Пишутся в stdout; в Docker смотрите `docker compose logs -f`.
- **Обновления.** Сделайте бэкап, обновите код, перезапустите. Схема БД
  версионируется через `PRAGMA user_version`.
- **Один экземпляр.** Не запускайте два процесса с одной SQLite-базой.
- **Права.** Роль бота должна быть выше всех ролей, которые он выдаёт,
  и выше ролей участников, которых он модерирует.

## Безопасность

- Дашборд не имеет паролей: вход только через Discord OAuth2.
- Доступ к серверу проверяется по правам `Manage Guild` / `Administrator`.
- Cookie сессии — `HttpOnly`, `SameSite=Lax`, при HTTPS — `Secure`.
- Сессии хранятся в БД и истекают через `SESSION_TTL_DAYS`.
- CSRF-токен обязателен для всех POST-форм.
- Не публикуйте `.env` и файлы базы.
- Для продакшена ставьте дашборд за HTTPS reverse proxy.

## Частые проблемы

**Команды не появились.**
Глобальная синхронизация может занять до часа. Укажите `DEV_GUILD_ID` для
мгновенной синхронизации на тестовом сервере. Проверьте, что бот приглашён
со scope `applications.commands`.

**Бот не выдаёт роли.**
У бота должно быть право «Управлять ролями», а его роль — стоять выше
выдаваемых ролей. Это же касается ролей за уровни, авторолей и магазина.

**Нет логов.**
Проверьте канал логов, включённые события и права бота на отправку сообщений
в канал. События из игнорируемых каналов и от игнорируемых пользователей
не логируются.

**Не работает вход в дашборд.**
Redirect URI в Developer Portal должен точно совпадать с
`DASHBOARD_URL/auth/callback`. Проверьте `DISCORD_CLIENT_ID` и
`DISCORD_CLIENT_SECRET`. На HTTPS cookie должны быть Secure — для этого
`DASHBOARD_URL` тоже должен быть `https://`.

**Discord пишет «Некорректный OAuth2 redirect_uri».**
Посмотрите, какой URI отправляет приложение:

```bash
curl -s -D - -o /dev/null http://127.0.0.1:8000/login \
  | grep -i '^location:' \
  | sed 's/.*redirect_uri=//; s/&.*//'
```

Добавьте в Developer Portal ровно этот URI. Если приложение отправляет
`http://localhost:8000/auth/callback`, открывайте дашборд через SSH-туннель
по `http://localhost:8000`, а не по `http://IP:8000`: иначе state-cookie
останется на IP, а callback придёт на localhost. Внешний `http://IP:8000`
Discord не принимает — для публичного дашборда нужен HTTPS-домен.

**Наказания не снимаются.**
Фоновая проверка идёт раз в 30 секунд. Если бот был выключен, наказания
снимутся после запуска. При ошибке прав дело закрывается с пометкой
в канале модерации.

**XP не начисляется.**
Проверьте, что система включена, сообщение не в игнорируемом канале,
у участника нет игнорируемой роли и не истёк кулдаун. Боты и системные
сообщения опыт не получают.

**В консоли Windows кракозябры вместо русского текста.**
Запустите `chcp 65001` или установите `PYTHONUTF8=1`.
